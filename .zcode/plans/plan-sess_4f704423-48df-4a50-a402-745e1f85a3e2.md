# CatPlan v0.4-alpha：完善功能闭环 + 国际化打底

## Context

v0.3.0 发布后盘点的真实缺口：**猫咪档案只能增不能改删**（名字/生日写错无法修正——CRUD 缺口）、**打卡误点无法撤销**（dailies 只进不出，连续天数会被误点污染）、**删除交互不统一**（照片有确认、健康日记没有）、**UI 文案大量硬编码中文**（F-Droid 国际化前的债）、**组件测试只在本地跑**（CI 未覆盖）、README 无截图门面。本轮全部补齐，版本推进 versionCode 8 / versionName 0.4.0-alpha01（不发 Release，全 E2E 后由用户确认发 v0.4.0）。

## 一、猫咪编辑 / 删除（核心）

- `AppViewModel.kt`：+ `updateCat(...)`（已有 catDao.update）、`deleteCat(cat)`（先 `PhotoStore` 清理该猫照片文件——文件名含 `cat_{catId}_` 前缀，再 `catDao.delete` 触发级联）、`regeneratePlan(cat)`（生日变更时：删该猫 pending 任务 → `CareScheduleGenerator.generate` 重生成）
- `AddCatDialog` 改造为 **`CatFormDialog(cat: CatEntity? = null)` 双模式**：编辑模式预填全部字段；生日可改——若生日变更，保存时提示「护理计划将按新生日重新生成」并执行 regeneratePlan
- `CatDetailScreen.kt`：头部加「编辑」「删除」按钮（删除走确认对话框，文案明示级联范围）；删除成功后 `popBackStack()`
- `CatsScreen.kt`：不变（点击进详情）

## 二、打卡撤销

- `CatPlanDao.kt`：+ `DailyDao.getForDay(type, catId, dateEpochDay)`（`catId` NULL 需 `IS NULL` 分支处理——用两条 @Query：按猫 / 全家）与 `delete(daily)`（已有）
- `TodayScreen.kt`：已打状态（`已喂 ✓`）的 chip 再点击 → AlertDialog 列出今日该类型打卡记录，每条带「撤销」→ 删除后 chip 回退、streak 自动回落（纯函数已算）
- 铲屎同理

## 三、删除确认统一

- `CatDetailScreen.kt`：健康日记条目点击 → 确认对话框（与照片删除同模式），替换现有直接删除

## 四、i18n 抽取（F-Droid 前置）

- `values/strings.xml`：全部硬编码中文文案迁入（今日/日历/档案/账本/设置五屏 + 对话框 + 通知 + widget，约 80 条，含 `%1$d` 占位符）
- 新增 `values-en/strings.xml` 英文全量翻译
- 六个 Screen 文件 + Widget 的硬编码文案全部替换为 `stringResource(R.string.xxx)`
- Widget（Glance）取串：`context.getString(...)`（provideGlance 非 composable 上下文）
- **测试同步**：`NavigationUiTest` 等断言文案改用 `composeRule.activity.getString(R.string.xxx)`，避免硬编码

## 五、CI 接入模拟器组件测试

- `.github/workflows/ci.yml`：新增 `instrumented-test` job——`reactivecircus/android-emulator-runner@v2`（API 34，arch x86_64）内跑 `connectedDebugAndroidTest`，失败时上传模拟器日志
