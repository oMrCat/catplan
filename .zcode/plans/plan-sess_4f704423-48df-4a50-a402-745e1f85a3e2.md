# CatPlan v0.3.0：包名对齐 + 发布工程 + 桌面小组件 + 健康日记

## Context

v0.3-alpha 功能已全部真机验证（打卡/生日提醒/体重曲线/备份恢复），但 ① 包名 `io.github.omrcat.catplan` 与 GitHub 账号不对齐（F-Droid 提交前迟早要改，现在只有测试数据是改名黄金窗口）② Release 一直挂 debug 签名 APK ③ 开源文档缺 CONTRIBUTING/Issue 模板 ④ 用户感知强的桌面小组件和猫奴刚需的健康日记还没做。本轮三线一次到位：**包名对齐 → 发布工程（签名 + CI 自动发版 + v0.3.0 正式版）→ 桌面小组件 → 健康日记 v1**。

## Phase A：包名重构 `io.github.omrcat.catplan` → `io.github.omrcat.catplan`

1. 目录移动：`app/src/main/java/io/github/catplan/app/**`、`test/**`、`androidTest/**` 同步移动到 `io/github/omrcat/catplan/**`（git mv）
2. 批量替换所有 `.kt/.xml/.md` 中 `io.github.omrcat.catplan` → `io.github.omrcat.catplan`（package/import/Manifest/Gradle namespace+applicationId）
3. Room schema 目录：`app/schemas/io.github.omrcat.catplan.data.local.CatPlanDatabase/` → 新全限定名目录
4. **数据迁移**（真机）：adb 驱动旧包导出备份 JSON 到 Download → 卸载旧包 → 装新包 → 导入恢复（猫/任务/账本/打卡全回；照片丢失——已知不参与备份，向用户明示）
5. 全量测试 + 真机冒烟验证

## Phase B：发布工程

1. **签名**：`keytool -genkeypair` 生成 `secrets/release.keystore`（目录 gitignore）；`keystore.properties`（gitignore）存密码；`app/build.gradle.kts` 读 properties 签名 releaseBuildType；CI 从 GitHub Secrets 读（用 `gh secret set` 自动写入 KEYSTORE_BASE64/STORE_PASSWORD/KEY_PASSWORD/KEY_ALIAS —— gh 已登录可全自动）
2. **CI 自动发版**：`.github/workflows/release.yml` 新文件——`on: push: tags: ['v*']`：解码 keystore → `assembleRelease` 签名 → `gh release create` 附 APK
3. **开源文档**：`CONTRIBUTING.md`（环境/分支/测试要求/发版纪律）、`.github/ISSUE_TEMPLATE/bug_report.md` + `feature_request.md`、`.github/PULL_REQUEST_TEMPLATE.md`
4. 版本：versionCode 7 / versionName **0.3.0**
5. 全功能真机 E2E 后 tag `v0.3.0` → 验证 CI 自动发版出**签名 APK**

## Phase C：桌面小组件（Jetpack Glance）

1. 依赖：`androidx.glance:glance-appwidget:1.1.1`
2. NEW `widget/TodayWidget.kt`（GlanceAppWidget）+ `widget/TodayWidgetReceiver.kt`：显示"猫计划·今日"标题 + 最新 2-3 条待办 + 喂食/铲屎打卡状态行；喂食/铲屎按钮用 `ActionCallback` 直接写 DB（复用 DailyDao）；点击卡片 `actionStartActivity` 深链今日页
3. Manifest 注册 receiver + `APPWIDGET_UPDATE` intent-filter；数据读取在协程中走 `CatPlanDatabase.get()`
4. 验证：`dumpsys appwidget` 确认 provider 注册；adb 触发更新；打卡按钮点击后 DB 与 UI 状态变化

## Phase D：健康日记 v1（结构化记录）

1. `Entities.kt`：+ `HealthNoteEntity(catId, dateEpochDay, appetite/energy/poop/urine: String?, text: String?, createdAt)`；DB v5 + `MIGRATION_4_5`
2. `CatPlanDao.kt`：+ `HealthNoteDao(observeForCat, insert, delete)`；`BackupCodec` schemaVersion 4 纳入 healthNotes（encode/decode/applyRestore 全链）
3. NEW `domain/HealthFlags.kt`：异常标记纯函数 `abnormalFlags(note): List<String>`（软便/腹泻/血尿/尿少/萎靡/食欲差 等白名单）→ 单测
4. `CatDetailScreen.kt`：+ 「健康日记」卡片——最近条目时间线（异常项警示色高亮）+ ＋记录对话框（4 组 FilterChip：食欲/精神/便便/尿液 + 文字备注）+ 长按删除
5. `AppViewModel.kt`：observeHealthNotes(catId) / addHealthNote / deleteHealthNote

## 不做（防范围膨胀）

通知操作按钮、多端实时协同、i18n 抽取（backlog）、WebDAV 真实服务器验证（需用户配坚果云）

## 验证

1. 每阶段本地：`gradlew :app:assembleDebug :app:testDebugUnitTest`（预期 37 → ~42 全绿）+ `connectedDebugAndroidTest`（7 用例）
2. Phase A 后真机：备份导出 → 卸载 → 新包安装 → 导入 → Mimi/豆豆/¥173.50/任务全回
3. Phase C/D 后真机：widget 注册与打卡联动；健康日记录入含异常项警示色
4. Phase B 后：本地 keystore 签名 APK 可安装；tag `v0.3.0` 推送 → CI 自动创建 Release 附**签名 APK**
5. 最终推送 main → CI 绿
